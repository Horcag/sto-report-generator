# STO Report Generator

STO Report Generator — это инструмент для автоматической генерации отчетов, курсовых и дипломных работ в формате `.docx` из удобной Markdown-разметки. Сгенерированные документы строго соответствуют требованиям ГОСТ и СТО Самарского университета.

## 🚀 Особенности
- Автоматическая генерация титульного листа по метаданным (YAML Frontmatter).
- Автоматическое формирование кликабельного оглавления (СОДЕРЖАНИЕ).
- Поддержка математических формул ($\LaTeX$) и их нумерации по правому краю.
- Форматирование списков по ГОСТ (маркеры в виде дефисов, строчные буквы).
- Встроенная система валидации Hanging References (проверка упоминания рисунков/таблиц до их появления в тексте).
- Автоматическая сборка библиографического списка из файла `.bib`.
- Строгое соблюдение отступов (1.25 см), шрифтов (Times New Roman, 14pt) и интервалов (1.5).

## 🛠 Установка

Для работы генератора требуются **Node.js** (для сборки) и **[uv](https://docs.astral.sh/uv/)** (для запуска Python-валидаторов).

```bash
# Установка NPM-зависимостей
npm install
```

## 📖 Использование

Генератор читает все `.md` файлы в указанной директории, сортирует их по алфавиту и склеивает в единый документ.

Вы можете изучить все возможности на базе встроенного примера:

```bash
# Сборка примера
npm run build example example/output.docx
```

### Структура папки отчета
Рекомендуется разбивать отчет на логические блоки с нумерацией в начале имени файла:
- `00_metadata.md` — содержит YAML-блок с параметрами титульного листа (название, группа, руководитель, тема и т.д.).
- `01_referat.md` — реферат работы. Используйте `\sto_structural_heading{РЕФЕРАТ}` для корректного заголовка.
- `02_toc.md` — содержит только тег `\sto_structural_heading{СОДЕРЖАНИЕ}` для вставки автособираемого оглавления.
- `03_intro.md` — введение.
- `10_main.md` — основная часть (может быть разбита на несколько файлов).
- `90_conclusion.md` — заключение.
- `91_sources.md` — список литературы. Используйте конструкцию `\begin{sto_bibliography} \end{sto_bibliography}`.

### Сборка собственного отчета
Создайте папку `reports/my_report` (папка `reports/` специально добавлена в `.gitignore`, чтобы ваши личные данные, черновики и дипломы случайно не попали в публичный репозиторий).

```bash
# Запуск сборки
npm run build reports/my_report reports/my_report/my_final_report.docx
```

## 🛡 Проверка на ошибки (Валидатор и Регрессия)

Проект содержит скрипты валидации, которые анализируют сгенерированный XML-код документа на соблюдение стилей (шрифты, отступы, выравнивание, правильные тире вместо дефисов, отсутствие капса там, где он не нужен).

```bash
# Собрать пример с прогоном всех тестов и пост-обработкой (рекомендуемый способ сборки)
npm run build:example

# Запустить валидатор вручную на готовом файле:
npm run validate example/output.docx
```
*(Примечание для Windows: Если возникают проблемы с кракозябрами в консоли при работе валидатора, установите переменную среды `PYTHONUTF8=1`)*.

## 🐛 Отладка (Unpack)
Файлы `.docx` технически являются zip-архивами с XML-документами внутри. Если вам нужно посмотреть, как сгенерировался внутренний код (например, для добавления новых фич):
```bash
npm run unpack example/output.docx example_unpacked
```
