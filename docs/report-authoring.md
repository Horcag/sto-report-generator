# Report Authoring Guide

Короткие правила для подготовки учебного отчета в STO Report Generator.

## Новый отчет

Создавайте папку через scaffold, а не копированием старой работы:

```powershell
npm run new:report -- my_lab --profile lab --dir reports/my_lab --title "Название темы"
```

Профиль выбирает обязательные структурные элементы и стартовые шаблоны:

- `nir` - НИР с рефератом, содержанием и источниками;
- `coursework` - курсовая с полным набором структурных элементов;
- `lab` - лабораторная без реферата и источников, пока в тексте нет cite-ссылок.

## Титульный лист

Титульный лист заполняется только через YAML frontmatter в `00_metadata.md`. Не редактируйте титульную страницу вручную
в DOCX: при следующей сборке она будет создана заново.

`profile`, `reportType`, `topicPrefix` и `degree` должны описывать один и тот же тип работы:

```yaml
---
organizationLines:
    - 'Министерство науки и высшего образования Российской Федерации'
    - 'Федеральное государственное автономное образовательное'
    - 'учреждение высшего образования'
    - '«Самарский национальный исследовательский университет'
    - 'имени академика С.П. Королева»'
reportType: 'Курсовая работа'
degree: 'по дисциплине «Статистический анализ данных»'
semester: 6
specialtyCode: '01.03.02'
topicPrefix: 'Тема курсовой работы'
topic: 'Название темы'
supervisorRole: 'Проверил'
gradeLine: 'Оценка ________________________'
year: 2026
---
```

Preflight предупреждает, если, например, `profile: lab`, а на титульном листе осталась «Курсовая работа» или тема НИР.
Также проверяются типы `semester/year`, диапазон семестра, реалистичный год, формат `specialtyCode` и шаблонные значения
в ФИО/теме.

Шапка организации по умолчанию берется из `src/shared/config/sto-rules.json`. Если для конкретной работы нужна другая
шапка, задайте `organizationLines` в `00_metadata.md`; это должен быть массив непустых строк.

Для курсовых можно заменить стандартную роль руководителя на строку проверяющего через `supervisorRole: 'Проверил'`.
Если на титульнике нужна строка для оценки, добавьте `gradeLine`. Строка печатается в блоке проверяющего перед подписью
студента.

## Структура Markdown

Файлы собираются по алфавиту. Держите один смысловой блок в одном `.md` файле: metadata, referat, intro, methodology,
data, results, conclusion, sources.

Структурные элементы пишутся только через macro:

```tex
\sto_structural_heading{ВВЕДЕНИЕ}
```

Обычные разделы пишутся Markdown-заголовками без ручной нумерации:

```markdown
# Методика исследования

## Исходные предпосылки
```

## Источники

Храните большую личную библиотеку в `references.bib`, но в тексте используйте только нужные ключи:

```markdown
Метод описан в работе [@ivanov2026].
```

`91_sources.md` должен оставаться пустым контейнером:

```tex
\sto_structural_heading{СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ}

\begin{sto_bibliography}
\end{sto_bibliography}
```

Генератор вставит только реально процитированные записи в порядке первого появления. Ручные номера `[1]` и ручной список
внутри `sto_bibliography` запрещены.

Preflight проверяет только процитированные BibTeX-записи. Неиспользованные записи в большой личной библиотеке могут быть
неполными и не будут шуметь.

Минимальные поля:

```bibtex
@book{samarsky1977,
  author = {Самарский, А. А.},
  title = {Теория разностных схем},
  address = {М.},
  publisher = {Наука},
  year = {1977},
  pages = {656}
}

@article{fursov2016,
  author = {Фурсов, В. А.},
  title = {Построение КИХ-фильтров в заданном параметрическом классе частотных характеристик},
  journal = {Компьютерная оптика},
  year = {2016},
  volume = {40},
  number = {6},
  pages = {878--886}
}

@inproceedings{conf2026,
  author = {Иванов, И. И.},
  title = {Название доклада},
  booktitle = {Материалы конференции},
  address = {Самара},
  organization = {Самарский университет},
  year = {2026},
  pages = {10--12}
}
```

Для электронных источников используйте URL с протоколом и дату обращения в формате `YYYY-MM-DD`:

```bibtex
@online{site2026,
  title = {Название страницы},
  year = {2026},
  url = {https://example.com},
  urldate = {2026-06-08}
}
```

Для англоязычных источников добавляйте `langid = {english}`. В поле `doi` пишите только DOI, без `https://doi.org/`.
Если источник является working paper, preprint, SSRN/arXiv/NBER material, не оформляйте его как журнальную статью
`@article`: используйте `@techreport`, `@misc` или `@online`.

Для книг поле `pages` означает общий объем, например `pages = {300}`. Диапазоны страниц `10--20` используйте для статей,
сборников и материалов конференций.

## Перечни

Не используйте raw Markdown-списки вне STO-окружений. Перед списком добавляйте вводную фразу, обычно с двоеточием:

```tex
Основные этапы включают:
\begin{sto_list}
- подготовку данных;
- обучение модели;
- проверку результата.
\end{sto_list}
```

Не оставляйте предлог перед списком:

```tex
Обратить внимание:
\begin{sto_list}
а) на корректность данных;
б) на полноту источников.
\end{sto_list}
```

Для `1)`, `а)` точка после скобки не ставится. Для `1.`, `I.`, `А.` пункт начинается с прописной буквы и заканчивается
точкой.

Не смешивайте на одном уровне разные маркеры и не пропускайте номера:

```tex
\begin{sto_list}
1) первый пункт;
2) второй пункт.
\end{sto_list}
```

## Таблицы, рисунки, формулы

Перед таблицей или рисунком сначала упомяните объект в тексте, затем вставляйте подпись:

```markdown
Основные характеристики приведены в таблице 1.

Таблица 1 – Основные характеристики (@tab:summary)
| Показатель | Значение |
|---|---:|
| Число наблюдений | 83 |
```

Формулы нумеруются только метками:

```markdown
Показатель задается формулой @eq:ratio:

$$y_i = \frac{x_i}{z_i} (@eq:ratio)$$
```

Пишите функции как LaTeX-команды: `\sin`, `\cos`, `\ln`, `\max`, `\min`, `\exp`. Для многоточия используйте `\ldots`,
`\dots` или `\cdots`, а не `...` или `…`. Сырые `×` и `∙` в Markdown не используйте: пишите `\times` или `\cdot`.

Не ставьте `\cdot` между числом и буквенным символом:

```markdown
$$
5x + 2y
$$
```

Не пишите номера формул вручную и не ставьте точку перед абзацем `где`:

```markdown
$$
y_i = \frac{x_i}{z_i} (@eq:ratio)
$$

где $y_i$ – расчетный показатель.
```

Если после формулы идет несколько определений, разделяйте их точкой с запятой, а последний элемент завершайте точкой:

```markdown
где $x_i$ – числитель; $z_i$ – знаменатель.
```

Если формула переносится через `\\`, не переносите ее на знаке деления. При переносе после `=`, `+`, `-`, `\times`
оператор должен повторяться в начале следующей строки.

## Проверка перед сборкой

Обычный цикл:

```powershell
npm run check:source -- reports/my_report
npm run generate:report -- reports/my_report --post-build --validate
```

Полный аудит одной командой:

```powershell
npm run audit:report -- reports/my_report
```

Перед сдачей включайте строгий режим:

```powershell
npm run check:source -- reports/my_report --strict
```

`WARN` не блокирует обычную сборку, но в `--strict` становится ошибкой.

## Приложения

Ставьте приложения после списка источников и ссылайтесь на них до заголовка:

```markdown
Подробные результаты приведены в приложении А.

\sto_structural_heading{ПРИЛОЖЕНИЕ А}
```

Рисунки, таблицы и формулы внутри приложений должны иметь нумерацию с буквой приложения (`А.1`). Пока генератор не
перенумеровывает их автоматически, preflight выдает `WARN`, если внутри приложения встречает обычную нумерацию `1`.
