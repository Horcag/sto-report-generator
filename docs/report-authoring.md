# Report Authoring Guide

Короткие правила для подготовки учебного отчета в STO Report Generator.

## Новый отчет

Создавайте папку через scaffold, а не копированием старой работы:

```powershell
npm run new:report -- my_lab --profile lab --dir reports/my_lab --title "Название темы"
```

Профиль выбирает обязательные структурные элементы и стартовые шаблоны:

- `nir` - НИР с рефератом, содержанием и источниками;
- `coursework` - курсовая с полным набором структурных элементов;
- `lab` - лабораторная без реферата и источников, пока в тексте нет cite-ссылок.

## Структура Markdown

Файлы собираются по алфавиту. Держите один смысловой блок в одном `.md` файле: metadata, referat, intro, methodology,
data, results, conclusion, sources.

Структурные элементы пишутся только через macro:

```tex
\sto_structural_heading{ВВЕДЕНИЕ}
```

Обычные разделы пишутся Markdown-заголовками без ручной нумерации:

```markdown
# Методика исследования

## Исходные предпосылки
```

## Источники

Храните большую личную библиотеку в `references.bib`, но в тексте используйте только нужные ключи:

```markdown
Метод описан в работе [@ivanov2026].
```

`91_sources.md` должен оставаться пустым контейнером:

```tex
\sto_structural_heading{СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ}

\begin{sto_bibliography}
\end{sto_bibliography}
```

Генератор вставит только реально процитированные записи в порядке первого появления. Ручные номера `[1]` и ручной список
внутри `sto_bibliography` запрещены.

## Таблицы, рисунки, формулы

Перед таблицей или рисунком сначала упомяните объект в тексте, затем вставляйте подпись:

```markdown
Основные характеристики приведены в таблице 1.

Таблица 1 – Основные характеристики (@tab:summary)
| Показатель | Значение |
|---|---:|
| Число наблюдений | 83 |
```

Формулы нумеруются только метками:

```markdown
Показатель задается формулой @eq:ratio:

$$y_i = \frac{x_i}{z_i} (@eq:ratio)$$
```

Не пишите номера формул вручную и не ставьте точку перед абзацем `где`.

## Проверка перед сборкой

Обычный цикл:

```powershell
npm run check:source -- reports/my_report
npm run generate:report -- reports/my_report --post-build --validate
```

Перед сдачей включайте строгий режим:

```powershell
npm run check:source -- reports/my_report --strict
```

`WARN` не блокирует обычную сборку, но в `--strict` становится ошибкой.
