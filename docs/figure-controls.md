# Figure controls

## Проверить и настроить рисунки

Инспектор читает изображения из Markdown выбранного отчёта. Учитывается `sourceDir` из `report.config.json`; повторные
вхождения одного файла остаются отдельными рисунками. ID берётся из следующей подписи `(@fig:scheme)`. Без метки
используется `figure-N`, где N – номер вхождения изображения во всём отчёте. Для устойчивой настройки добавьте метку
в подпись: вставка другого изображения меняет номера безымянных рисунков.

```sh
npx tsx src/index.ts figures inspect reports/my_lab --json
npx tsx src/index.ts figures preview reports/my_lab --output /tmp/my_lab-figures.html
```

Откройте HTML в браузере. Выберите рисунок, задайте ширину в миллиметрах и проценты обрезки с каждой стороны.
Инспектор показывает исходник, видимую область и размер на условном листе A4. Можно сравнить варианты без изменения
изображения. Проверьте, что за краем не оказались подписи осей, стрелки, номера элементов и легенда. HTML содержит
реальные изображения отчёта; храните и передавайте его с теми же ограничениями, что и исходники.

Кнопка «Скачать figures.json» сохраняет настройки браузера. Затем примените файл к исходникам:

```sh
npx tsx src/index.ts figures set reports/my_lab --settings /path/to/downloaded/figures.json
```

Для одного рисунка можно передать настройку непосредственно:

```sh
npx tsx src/index.ts figures set reports/my_lab --id scheme --spec '{"widthMm":120,"crop":{"left":5,"right":5,"top":0,"bottom":0}}'
```

Команда проверяет настройки и доступность файлов до замены `figures.json`, затем читает сохранённый файл обратно.
Некорректная ширина, обрезка или путь оставляют прежние настройки. Настройки хранятся рядом с Markdown в каталоге
`sourceDir`; пути изображений остаются относительными к этому каталогу. После сохранения повторите просмотр
и сборку отчёта. Изменения в открытом HTML сами по себе не меняют DOCX.

## Настройки и качество

```json
{
	"defaults": {
		"maxWidthMm": 140,
		"maxHeightMm": 230,
		"minDpi": 150,
		"minTextPt": 9,
		"quality": "warn"
	},
	"figures": {
		"scheme": {
			"source": "images/scheme.svg",
			"fallback": "images/scheme.png",
			"widthMm": 120,
			"crop": { "left": 5, "right": 5, "top": 0, "bottom": 0 }
		}
	}
}
```

Указанная ширина должна помещаться в пределы ширины и высоты. Обрезка задаётся в процентах исходного изображения
и должна сохранять положительную область. Генератор сохраняет исходные байты; обрезка переносится в DOCX как
редактируемая область изображения. В Word доступны обычные команды размера и обрезки, без дополнения.

DPI измеряет плотность растровых пикселей в конечном размере. Высокий DPI не делает мелкие подписи читаемыми.
Для растра `textSizePx` задаёт измеренный минимальный размер текста в исходнике; инспектор пересчитывает его в
пункты на странице. Без такого измерения размер текста неизвестен. Для простого SVG размер можно определить
по атрибутам текста; сложные стили, преобразования и текст в контурах могут оставлять его неизвестным.
У SVG отдельно оценивается плотность резервного PNG. Значение `quality: "error"` переводит замечания качества
в ошибки; пороги нужно выбирать по требованиям конкретной работы.

В draw.io сохраняйте редактируемый файл диаграммы отдельно, а для отчёта экспортируйте переносимый SVG с обычным
текстом и настоящий PNG той же геометрии. PNG служит резервом для Word; переименование SVG в `.png` не создаёт
растровое изображение. Если экспорт зависит от внешних ресурсов, сначала проверьте его переносимость.
Повторяющийся заголовок внутри изображения можно убрать, если подпись рисунка передаёт тот же смысл и обозначения
допускают это. Заголовки осей, легенду и названия элементов сохраняйте.

Для большого набора схем задайте общие ограничения, например `maxWidthMm: 140` и `maxHeightMm: 220`,
а каждому рисунку назначьте устойчивый ID в подписи. Если требуется ровно 140 мм по ширине, укажите `widthMm: 140`
для каждого ID. Высокая схема при такой ширине может превысить предел высоты; инспектор покажет ошибку,
после которой нужно уменьшить ширину или разделить схему. Пропорции сохраняются с учётом выбранной обрезки.

Минимальный текст простого SVG оценивается по размеру шрифта и геометрии. Для SVG со стилями, преобразованиями,
вложенными элементами или текстом в контурах результат может быть неизвестен. Это требует проверки отрисовки
и шрифтов на конечной странице. Геометрические проверки не распознают смысл символов диаграммы: намеренно
открытая граница хранилища DFD не считается доказательством обрезанного экспорта. Сверяйте края, стрелки и текст
с исходной редактируемой схемой; предупреждение об обрезке означает необходимость такой сверки.

## Положение текста в SVG

Размер шрифта и сохранность SVG не подтверждают положение надписей в Word. Атрибуты `dominant-baseline`
и `alignment-baseline` выбирают базовую линию, относительно которой размещаются символы. Например,
`dominant-baseline="text-before-edge"` может правильно выглядеть в браузере, а в Word сместить текст вверх.
Высокий DPI резервного PNG и успешная проверка `minTextPt` не устраняют это различие.

Планирование выдаёт `svg-baseline-compatibility` для объявлений, кроме `auto`/`alphabetic` у `dominant-baseline`
и `baseline`/`alphabetic` у `alignment-baseline`. Проверяются текст, его предки, встроенные стили и блоки CSS.
Проверка объявлений консервативна: она не вычисляет селекторы и каскад, поэтому может отметить неиспользуемое
правило CSS или атрибут предка, переопределённый у текста.
В режиме `quality: "warn"` исходник сохраняется и замечание остаётся в инспекторе при изменении размера.
В режиме `quality: "error"` проверка исходников и сборка отклоняют такой рисунок. Это проверка риска совместимости;
она не объявляет перечисленные свойства недопустимыми в SVG и не доказывает одинаковое поведение всех версий Word.

Для переносимой схемы задавайте `y` как явную координату алфавитной базовой линии, без этих управляющих атрибутов:

```xml
<text x="40" y="80" font-family="Arial" font-size="36">Надпись</text>
```

Если надпись должна быть по центру строки, вычисляйте координату по метрикам выбранного шрифта, а не считайте `y`
верхним краем текста. При наличии границ видимых символов относительно базовой линии используйте
`y = центр_строки − (верх_символов + низ_символов) / 2`; все величины должны быть в одних единицах SVG.
Замена шрифта может изменить результат, поэтому проверьте наличие нужного шрифта на машине с Word.
Генератор не удаляет атрибуты и не сдвигает текст автоматически: такое исправление требует знания исходной схемы.

Обычные значения базовой линии также не дают полной гарантии: наследование, вертикальное письмо,
сложный CSS и другие способы размещения требуют просмотра итогового DOCX/PDF. Свойства и их значения описаны
в [SVG 2](https://www.w3.org/TR/SVG2/text.html#DominantBaselineProperty) и
[CSS Inline Layout](https://www.w3.org/TR/2024/WD-css-inline-3-20241218/#dominant-baseline).
Извлечение текста из PDF проверяет отдельное свойство: некорректная карта Unicode у встроенного шрифта может
исказить извлечённые символы, даже если подписи выглядят правильно. Сверяйте исходный текст, положение и внешний вид раздельно.

## Проверить результат в Word

Просмотр на условном листе показывает геометрию рисунка. Переносы, соседние абзацы и разбиение страниц проверяйте
в собранном DOCX и PDF. При ручной правке размера или обрезки в Word перенесите значения в `figures.json` и повторите
сборку: изменения в DOCX не импортируются автоматически и будут заменены следующей сборкой.

В параметрах Word для текущего документа проверьте флажок «Не сжимать изображения в файле» и разрешение изображений.
Сам флажок не доказывает сохранение качества уже вставленной картинки. Для проверки сравните байты или размеры
изображений в `word/media` и параметры обрезки/размера в XML до и после открытия и сохранения Word.
Приёмку запускайте через ограниченный по времени штатный launcher:

```sh
npm run accept:word -- /path/to/report.docx
```

Сохраните отчёт проверки и просмотрите итоговые страницы. Успешная сборка, отсутствие ошибок геометрии и Word-приёмка
показывают разные свойства; читаемость мелких подписей требует проверки конечного изображения на странице.

## Качество экспорта PDF

Сохранение исходных изображений в DOCX и качество PDF проверяются отдельно. Word может сохранять байты рисунка
в `word/media`, но уменьшать его разрешение при экспорте PDF. Флажок документа «Не сжимать изображения в файле»
сам по себе не подтверждает качество PDF.

Штатная приёмка вызывает `Document.ExportAsFixedFormat2` с `OptimizeForImageQuality=true`, запрашивая сохранение
качества изображений при экспорте. Параметр описан в [документации Microsoft](https://learn.microsoft.com/en-us/office/vba/api/word.document.exportasfixedformat2).
Если версия Word не поддерживает этот метод, launcher использует прежний экспорт и записывает предупреждение
о неподтверждённом качестве. Ошибки самого экспорта не переключают его на менее качественный режим.

В отчёте приёмки `pdf.export` содержит метод и применённый параметр; `qualityStatus` остаётся
`unverifiedUntilPdfInspection`. Для подтверждения качества измерьте размеры растров и их DPI на итоговой странице PDF,
затем проверьте читаемость подписей, легенды и осей. Успешный вызов API не заменяет измерение конечного файла. На проверенной установке Word 16.0.20430 этот параметр
не предотвратил уменьшение изображения с 1800×900 до 1102×551 пикселя при ширине 140 мм — примерно 200 DPI.
Сохранность исходного DOCX в этом случае была подтверждена отдельно; сохранность разрешения PDF — нет.
