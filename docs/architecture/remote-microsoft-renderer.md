# Удалённый Microsoft renderer: результат исследования

Проверено 24 сентября 2026 года по документации Microsoft Graph v1.0. Этот документ описывает возможный маршрут, но не вводит сетевой renderer в CLI: для него пока нет учётной записи, согласованной политики отправки отчётов и приёмочного сравнения с Word Desktop.

## Microsoft Graph / OneDrive

Graph умеет преобразовать загруженный `docx` в PDF через `GET /me/drive/items/{item-id}/content?format=pdf`. `docx` указан среди поддерживаемых исходных форматов. Для чтения достаточно delegated `Files.Read`; для предварительной загрузки файла нужен delegated `Files.ReadWrite` (или более широкий application scope). Малые файлы до 250 МБ можно загрузить одним `PUT`; крупные требуют upload session. Ответ конвертации перенаправляет на временный URL загрузки PDF.

Рабочий протокол для будущей opt-in реализации: создать временный объект в управляемом каталоге OneDrive, загрузить DOCX, запросить PDF, скачать и проверить PDF, записать ID объекта и срок хранения в локальный manifest, затем удалить временный объект. Токен и URL загрузки нельзя помещать в журнал или manifest. Сам отчёт и все вложенные изображения покидают локальную машину; использование должно требовать явного выбора пользователя и подходящего корпоративного tenancy. Следует учитывать задержку индексации/конвертации, ошибки Graph, квоты и контролируемое удаление временного объекта.

Graph не обещает совпадения страниц, переносов и полей с локальным Word Desktop. Поэтому результат может быть только альтернативным PDF preview до отдельного сравнительного испытания на одном содержимом и фиксированных шрифтах. DOCX без обновлённых Word-полей также не становится автоматически принятым DOCX от одного скачивания PDF.

## Собственный Windows renderer

Второй маршрут — выделенный Windows host с установленным Microsoft Word, исполняющий существующий контракт `accept-word` по очереди заданий. Для реализации понадобятся аутентификация клиента, шифрованная передача отчёта, изоляция задания и рабочего профиля, фиксированные шрифты/принтер, таймаут, точное владение процессами Word, очистка временных файлов и возвращаемый manifest с хешами. Этот маршрут ближе к текущей локальной приёмке, но требует отдельной инфраструктуры и проверки на реальном host; простой удалённый вызов не доказывает идентичность окружения.

## Решение

Оставить `portable` для локального DOCX и `accept-word` для авторитетной Word/PDF-приёмки на доступном Windows host. Не добавлять Graph credentials и сетевую передачу отчётов в текущий CLI. Если появится требование работы без локального Word, следующим отдельным этапом сделать ограниченный прототип Graph PDF preview на обезличенном документе и сравнить страницы с Word Desktop; после этого выбирать между Graph и управляемым Windows host.

Источники: [Graph conversion](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content-format?view=graph-rest-1.0), [Graph upload and permissions](https://learn.microsoft.com/en-us/graph/api/driveitem-put-content?view=graph-rest-1.0).
