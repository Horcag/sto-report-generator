# Строгая типографика СТО

`sto-strict` – опциональный набор правил для выбранной буквальной трактовки
оформления СТО 2018 года в издании 2019 года. Он не меняет штатный
`samara-template-2022` и переносимый режим `default`.

## Выбор режима

В `report.config.json` укажите:

```json
{
	"stylePreset": "sto-strict"
}
```

Для отдельного запуска используйте `--style-preset sto-strict`:

```bash
npx tsx src/index.ts check reports/my_report --style-preset sto-strict
npx tsx src/index.ts generate reports/my_report --style-preset sto-strict --renderer portable --validate
npx tsx src/index.ts audit reports/my_report --style-preset sto-strict --renderer portable
npx tsx src/index.ts build input.md output.docx --style-preset sto-strict
npx tsx src/index.ts input.md output.docx --style-preset sto-strict
```

CLI переопределяет `stylePreset` конфигурации в `check`, `generate` и `audit`,
а в `build` и старой форме прямого вызова – значение YAML metadata. При отсутствии
параметра действуют прежние значения и правила выбора. `check` проверяет исходники;
он не создаёт DOCX и не доказывает соответствие итогового оформления.

Флаг `check --strict` имеет прежнее значение: предупреждения проверки исходников
блокируют успешное завершение. Этот флаг и `preflight.strict` не выбирают набор
оформления. Можно использовать оба параметра одновременно.

## Типографика и исключения

- Обычный текст, включая заголовки, титульный лист, подписи и текст таблиц,
  формируется шрифтом Times New Roman 14 пт без полужирного начертания.
- Моноширинное оформление встроенного кода и блоков кода заменяется той же
  текстовым оформлением. Содержимое кода сохраняется.
- Для обычных абзацев применяется полуторный интервал. Сохраняются специальные
  правила многострочных подписей таблиц и математической разметки.
- OMML сохраняет математическую семантику, включая полужирные математические
  символы и математические шрифты. Запрет полужирного относится к текстовым
  фрагментам и не снимает смысловое начертание внутри формулы.
- В `generate` и `audit` вставляемый `frontMatterDocx` также проходит нормализацию
  после вставки и до рендеринга Word.

## Проверка результата

DOCX содержит маркер режима. Поэтому обычный вызов распознаёт строгий документ
без отдельного флага:

```bash
npx tsx src/index.ts validate-docx output.docx unpacked
```

Генератор задаёт 14 пт. Строгая проверка допускает текстовый кегль 12–14 пт
(значения `w:sz` и `w:szCs` от 24 до 28 единиц по 0,5 пт), проверяет применимые
текстовые свойства и учитывает математические исключения. Маркер обозначает
выбранный режим; успешный результат устанавливается при проверке файла.

Режим ограничен реализованными XML-проверками оформления и существующими
проверками генератора. Он не является универсальной сертификацией СТО и не
проверяет полностью смысл работы, применимость всех норм, достоверность источников
или визуальную вёрстку каждого возможного документа. Для окончательной пагинации
и PDF используйте обычный workflow с `--renderer word` и проверяйте итоговый документ.
