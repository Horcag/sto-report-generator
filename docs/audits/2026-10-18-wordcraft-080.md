# Wordcraft 0.8.0 upgrade, 18 October 2026

## Scope

The optional renderer now requires Wordcraft CLI **0.8.0**, release commit
`f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22`. The default renderer remains portable;
Word acceptance remains separate. Earlier evidence is in the [0.7.0 audit](2026-10-17-wordcraft.md).

The official Linux x86-64 archive was checked against the GitHub release asset SHA-256:
`0ece07cf3d91b923dfd80f90310e04983bde66f0279c6b60ddce89596dde0ddf`.
The CLI reports `wordcraft-cli 0.8.0`. No upstream binary is committed or downloaded at render time.

## Comparison on identical generated DOCX files

The three public live controls were generated once and rendered with both 0.7.0 and 0.8.0
under Linux/WSL. Both paths explicitly updated fields and converged the referat page count.
The original DOCX hashes remained unchanged. No private reports were used.

| Control                          | 0.7.0 PDF pages | 0.8.0 PDF pages | Independent 0.8.0 checks                                                             |
| -------------------------------- | --------------- | --------------- | ------------------------------------------------------------------------------------ |
| Public example                   | 8               | 8               | Numbered TOC entries; correct referat total; 1200 by 600 image present               |
| Style corpus extended to 90 rows | 11              | 11              | Rows 1 through 90 in order; table on pages 6 through 8; header repeated on all three |
| Math and appendix                | 5               | 5               | Correct referat total; appendix TOC entry; sum, integral and matrix present          |

Independent inspection used the bundled document runtime: pypdf 6.10.0 for PDF page trees,
searchable text and image resources, and PDFium for page rasterization. Statistics and stale
placeholder checks passed on all three PDFs. Source and PDF hashes were read back.

All 24 pages were raster-compared with the corresponding 0.7.0 pages. Representative TOC,
formula and table pages were also visually inspected. The example TOC now includes `1`, `1.1`,
`1.2` and `1.3`, which were absent in 0.7.0. The main formula page was pixel-identical.
The 90-row table retained its rows and repeated headers. Equal page totals do not establish
full Word layout equivalence.

## Regression coverage

The live suite now injects a stale cached TOC result with `w:dirty`, updates it through the
installed CLI and checks that the placeholder disappears, numbered entries remain inside the
TOC field, the dirty flag clears and the source remains unchanged. The probe passes with
0.8.0; 0.7.0 fails the numbered-entry assertion. Normal tests accept 0.8.0 and reject both
0.7.0 and an untested future version. Help and doctor tests pin the advertised requirement.

## Native Word comparison

The example and math/appendix sources passed `npm run accept:word`: Microsoft Word 16.0
build 16.0.20430 updated fields and TOC, saved and reopened at stable 8 and 5 pages,
verified required styles and figure integrity, and exported PDFs. Both acceptance receipts
report `processCleanupVerified: true`; source, accepted DOCX and PDF hashes were read back.
The Office license diagnostic reported a warning; the actual document operations passed.
This accepts the two generated DOCX controls in Word, not the Wordcraft PDFs as Word-equivalent.
The 90-row table was checked in Wordcraft and independent PDF tools; native Word acceptance
was not run for that extended control.

## Relevant upstream changes

- [Numbered headings in TOC entries](https://github.com/storytold/wordcraft/pull/1470).
- [TOC page tabs and imported range placement](https://github.com/storytold/wordcraft/pull/1686).
- [Clear stale imported TOC results](https://github.com/storytold/wordcraft/pull/953) and
  [preserve dirty field state until computation](https://github.com/storytold/wordcraft/pull/946).
- [Table row margins and page splitting](https://github.com/storytold/wordcraft/pull/1177), and
  [long-table layout caching](https://github.com/storytold/wordcraft/pull/1492).
- [Embedded DOCX fonts used by layout and PDF](https://github.com/storytold/wordcraft/pull/1176), and
  [preservation of additional DOCX parts](https://github.com/storytold/wordcraft/pull/1060).

## Boundaries

The production manifest still says `pdfPageCountVerified: false` and `wordAccepted: false`:
the independent checks above belong to these exact test artifacts, not every future export.
Native Wordcraft on Windows and macOS, embedded-font behavior, large-table performance and
arbitrary imported DOCX fidelity have not been accepted by this upgrade comparison.
The generator retains validated SVG/PNG companions and rejects untested CLI versions.

Commands and artifact-retention controls: [renderer documentation](../architecture/wordcraft-renderer.md).
