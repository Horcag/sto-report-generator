## Version and comparison boundary

The opt-in renderer requires official CLI **0.11.0**, released on 25 October 2026,
commit `e31f2f06a5f8004ceaa88f68c00b47908e321aa4`.

| Download                 | Verified SHA-256                                                   |
| ------------------------ | ------------------------------------------------------------------ |
| Linux x86-64 tar.gz      | `034c247bf6dab172a2edfb0767de9065125b857826c6915f7ef39b9f43951d5a` |
| Windows x64 portable ZIP | `761a832f91a4bedcfacc62126ac31f78d5172fa10932b55bb6a587c797e38bea` |

Both archives were independently hashed against the official release checksums.
The previous CLI remains available for rollback and same-source comparisons.

The generator has changed since the [0.10.0 audit](2026-10-23-wordcraft-0100.md), including
canonical Word table styles and original-resolution PDF image export. Consequently this audit
freezes current DOCX inputs and processes each with both 0.10.0 and 0.11.0. Numbers from different
audits must not be treated as an engine-only comparison.

The initial nine inputs contain both public style presets, the 90-row table, math/appendix,
large/nested/rectangular matrices, three sections, release controls, and two frozen private reports.
Two additional private inputs are separately rebuilt with the current generator. Originals and
report Markdown are preserved; rebuilt artifacts have distinct hashes and case names.
Private source text, pictures and PDF copies are not published.

Times New Roman faces, Cambria Math/Cambria, Arial, Calibri and Courier New are supplied from
the same local licensed files. Font preflight, selected font hashes and input/PDF hashes are checked.
Wordcraft rendering remains experimental and does not mark an arbitrary PDF as Word-accepted.

## What upstream shipped

- [#3815](https://github.com/storytold/wordcraft/pull/3815): table rows must fit with their bottom
  border; repeated-header fit checks include the same edge allowance.
- [#3836](https://github.com/storytold/wordcraft/pull/3836): multiple-spaced final lines can use
  excess leading in the bottom margin when the actual text fits. Tall footers and footnotes
  remain restrictions. This is relevant to 1.5-spaced STO paragraphs.
- [#3816](https://github.com/storytold/wordcraft/pull/3816): keep-with-next uses the common
  0.01-point fit tolerance.
- [#4039](https://github.com/storytold/wordcraft/pull/4039): localized TOC style IDs are mapped to
  canonical TOC styles; two-column section boundaries and page-number tabs are handled better.
- [#4067](https://github.com/storytold/wordcraft/pull/4067): East Asian and complex-script font
  hints no longer replace the Latin font. Some ambiguous-punctuation hints remain unsupported.
- [#4092](https://github.com/storytold/wordcraft/pull/4092): saving an engine-created document
  with an unset font size no longer changes its resolved default from 11 to 10 points. This
  does not establish Word-default equivalence for arbitrary imported documents.
- [#4171](https://github.com/storytold/wordcraft/pull/4171): shared budget-aware picture decoding.
  Large inputs can be refused or replaced with a grey placeholder; a successful export alone
  does not prove image completeness.
- [#4184](https://github.com/storytold/wordcraft/pull/4184): PDF link filtering/geometry validation
  and metadata changes. Binary differences can therefore exist without visible layout changes.

The math layout file has the same Git blob in 0.10.0 and 0.11.0:
`6180fad39bc0bcddfe87f6b92e6bad25c638059d`.
[The MathLeading proposal #2674](https://github.com/storytold/wordcraft/pull/2674) was still open
on 26 October. No new general matrix/equation-spacing fix is attributed to this release.

## Integration fixes and retained safeguards

The exact raw TOC update/save probe still puts entries outside the matching outer field in
0.11.0. Preparing only the temporary semantic TOC control restores stale-result removal,
cleared dirty state and numbered entries **inside** that field. The canonical DOCX stays unchanged.
The existing import workaround and strict field-boundary tests are retained; its warning no
longer implies that the problem is confined to 0.10.0.

The three-section public fixture had left-aligned headings that no longer passed current table
rules. It now uses the same centered header paragraphs as the generator. Tests cover all five
header paragraphs and 203 body paragraphs in each preset; body alignment remains unchanged.
The corrected input is rebuilt for both engines and Word, rather than mixing fixture revisions.

Rebuilding the private NIR exposed a separate generator failure: its valid 5288x4737 PNG exceeded
the old fixed 64 MiB inflate limit. PNG validation now computes the exact row size before
inflation, rejects unsafe arithmetic and sizes above 128 MiB, and permits only that exact size
plus one sentinel byte during decoding. Exact output length, filters, CRC, chunk/palette order
and Adam7 validation remain enforced. The real report rebuild succeeds without resizing its
picture. Twelve regression cases cover the large image and malformed/budget-bound inputs.

## Native Word method and input limitations

Word runs only through `npm run accept:word -- <docx> --background-only`: no interactive retry,
Computer Use, keyboard/mouse automation or desktop focus. Successful references require stable
saved/reopened pagination, verified content integrity and verified owned-process cleanup.

The two frozen legacy DOCX files are rejected by the current STO table validator: their data
headings inherit left alignment. C1 has 50 source violations; continued copies account for 56
violations after Word pagination. The old R1 has seven post-Word violations. These are existing
input-formatting problems, not a 0.11 regression. Neither acceptance nor the validator is relaxed.
Their engine-to-engine comparison is retained, but they are excluded from accepted-Word parity.
The separately rebuilt current reports provide accepted large-document references.

The example/default/90-row controls contain SVG pictures. The original-pixel preservation mode
cannot prove those vector layouts. Their Word references therefore explicitly request
`--pdf-image-quality print`, which permits raster downsampling and requires separate PDF inspection.
This supported comparison mode is recorded in receipts; it is not an original-pixel guarantee.
Other accepted controls retain `original` mode, including the rebuilt private reports.

## Measured comparison with accepted Word references

The nine accepted references total **142 Word pages**; both engine versions total **141 pages**.
The rebuilt coursework remains 69 pages in Word versus 68 in both engine versions. All other
accepted controls have matching page counts. The coursework mean below includes its one unmatched
Word page as zero; always read the metric together with page counts. Same counts do not prove equivalent layout.

The rebuilt NIR moves closer to Word under this raster metric (6.863% to 6.304%).
The rebuilt coursework moves slightly farther away (13.154% to 13.191%). There is no uniform
improvement. The public controls have zero observed raster/text/geometry change between
0.10.0 and 0.11.0 at the stated DPI/tolerance, despite different PDF hashes.

The current matrix control takes **four pages in all three workflows**. Its equal count differs
from the previous audit because the generator/styles and input were rebuilt; it is not a new
matrix-renderer fix. Word and Wordcraft still differ in positions/spacing (2.606% mean changed
pixels on this control). Full-height delimiters are preserved.

The two unchanged legacy artifacts also keep their engine page counts: C1 has 66 and R1 has 26
in both versions. They remain separate from the accepted current-report measurements above.
All four large input pairs have identical encoded image streams, decoding parameters and alpha
masks between the engines: 13 + 6 + 13 + 6 image objects. Thus the new image probe has not replaced
or altered those tested pictures. This is a stronger statement than a successful export or a
resource-count check, but does not certify untested picture formats/limits.

## Platform result

All eleven final inputs produce **byte-identical 0.11.0 PDFs on Linux/WSL and native Windows**,
233 pages in each set. Independent page geometry, text, resources and 96-DPI raster checks agree.
This includes the nine accepted-Word inputs and the two separately labelled legacy inputs.
The latter still fail current STO heading checks; platform agreement does not change that status.

## Measurement method and limits

Independent PDF checks use pypdf, PDFium and Pillow, at 96 DPI and channel tolerance 16.
Text, page geometry, resources, unmatched pages and raster differences are separate measurements.
Pages are paired by ordinal; reflow is not realigned. Pixel fractions include white page area and
are not percentages of correct formatting. Page totals can hide opposite pagination errors.

CLI execution on Linux/WSL and native Windows is separate from CI code portability checks.
No native macOS, standalone physical Linux, ARM or RISC-V renderer run is claimed.
The Windows audit uses a path-translation bridge from WSL; its command-startup overhead is not
a native performance benchmark. A timed-out table attempt is retried with an explicit bounded
API audit budget, and task-owned CLI process absence is checked before cleanup.

Upstream retains [mathematical-default limitations](https://github.com/storytold/wordcraft/blob/v0.11.0/docs/file-format-parity.md)
and [font/table/layout gaps](https://github.com/storytold/wordcraft/blob/v0.11.0/docs/layout-parity.md).
Its corpus statistics do not certify this project's templates or arbitrary STO/ГОСТ requirements.

The PDF decoder retains a 512 MiB image budget and a 30,000-pixel side limit; the new shared
probe can reject some inputs earlier. Screen-cache downsampling is a separate path. The tested
5288x4737 PNG is below these engine limits. Oversized pictures still need explicit checks because
a grey placeholder can be emitted without a failing CLI exit status.

Practical limits and manual checks are maintained in the [compatibility matrix](../wordcraft-compatibility.md).
Full temporary engine archives, report copies, PDFs and logs are removed after compact evidence
capture; current installations, rollback versions and user originals are preserved.
