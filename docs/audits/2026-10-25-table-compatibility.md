## Safe boundaries

The selected university profile follows the teaching STO's page-end boundary exception. GOST's ordinary perimeter rule and the STO exception are not falsely attributed to the same clause. A general-purpose GOST-only profile is not claimed.

The project supports explicit next-page table continuations and renderer-measured pagination. A source paragraph `Продолжение таблицы N` starts the next segment on a new page; the preceding segment therefore uses the STO boundary exception. Same-page horizontal/column partitions remain author supplied. The parser cannot know a physical page boundary from a row count. A single large table is split only after the renderer supplies page positions; unsafe vertical merges, duplicate header identities and ambiguous containers are rejected with a concrete diagnostic.

Header text, data text and following prose now have named paragraph roles. Table geometry remains a table property. Named styles are available for inspection in Word; the complete template-style transfer and deliberate adaptations are documented in the [style audit](../architecture/dotm-template-style-audit.md).

## Running the checks

Run `npm run check:source -- <report>` and `npm run generate:report -- <report> --renderer portable --validate` for source and XML checks. These commands do not claim native Word pagination. Run `npm run accept:word -- <docx>` for the launcher-controlled Word save/PDF/cleanup route, then validate the accepted DOCX.

The full regression runner includes the table suites and shared separation cases. The Word acceptance integrity gate checks the saved artifact rather than assuming Word preserved the original properties. Concrete execution receipts belong to the PR evidence; a suite name in this matrix does not by itself mean that a live Word scenario passed.
