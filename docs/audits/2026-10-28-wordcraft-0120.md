# Wordcraft 0.12.0: measured Word compatibility

## Version and comparison boundary

The opt-in renderer requires official CLI **0.12.0**, released on 28 October 2026,
commit `3de6ff95af86c19d67030cd96dba15cd6a45a25e`.
The [official release](https://github.com/storytold/wordcraft/releases/tag/v0.12.0)
and [tag comparison](https://github.com/storytold/wordcraft/compare/v0.11.0...v0.12.0)
are the upstream sources. Archives are checked against the official SHA256SUMS before use.
The previous installed CLI is preserved for rollback.

This audit freezes DOCX inputs produced by generator revision
`ff27079be8abb04750126f7e8b6e6e04a7cc156c`, then processes the same bytes with
0.11.0, 0.12.0 and the supported native Word acceptance workflow. The generator's
math/gallery changes since the previous audit are therefore shared by both engines.
Numbers from different audits must not be interpreted as engine-only improvements.
Original private report sources and DOCX files are preserved; current rebuilds are separate inputs.

Thirteen inputs cover both style presets, a 90-row table, math/appendix, matrices up to
8x8 including rectangular and nested cases, three sections, previous release controls,
two legacy private DOCX files, two current private report rebuilds, and two new whitespace
controls. The new controls differ in the document-wide `doNotExpandShiftReturn` setting.
Linux runs load Times New Roman, Cambria Math/Cambria, Arial, Calibri and Courier New
from the same local licensed files, with matching loaded-file hashes between versions.
Windows finds its installed fonts in the native catalog and does not reload families
already available there. Strict family preflight passes on both hosts; the manifests
do not independently hash the files selected from the native Windows catalog. Exact
PDF identity establishes the observed output agreement, not that missing font provenance.

## What upstream shipped

- [#4210](https://github.com/storytold/wordcraft/pull/4210): U+00A0 uses ordinary-space width
  during shaping while remaining non-breaking. Narrow no-break space, figure space and
  Chart/SmartArt labels are outside that change. Fonts whose two glyph advances already
  agree need not produce a visible difference.
- [#4211](https://github.com/storytold/wordcraft/pull/4211): zero-width bookmark markers no
  longer create artificial wrapping opportunities or empty lines.
- [#4023](https://github.com/storytold/wordcraft/pull/4023): justified lines ending in a manual
  break expand unless `doNotExpandShiftReturn` suppresses it; DOCX import/export carries the flag.
- [#3936](https://github.com/storytold/wordcraft/pull/3936): continuous-section overflow moves
  to the next page and consecutive empty section marks occupy lines up to the page bottom.
  The existing three-section control does not establish coverage of every continuous-section case.
- [#4602](https://github.com/storytold/wordcraft/pull/4602): faster PDF export, with unchanged
  PDF/PNG bytes in upstream's benchmark. Its roughly 24% claim is not a measured speedup
  for this project's reports or the WSL-to-Windows path bridge.
- [#4242](https://github.com/storytold/wordcraft/pull/4242): LaTeX no-bar fraction/binomial
  roundtrip improvements. This is not a general DOCX matrix layout fix.
- [#3870](https://github.com/storytold/wordcraft/pull/3870): bounded render/PDF/metafile work.
  Resource limits can suppress oversized glyphs or simplify pathological dash patterns;
  successful export alone remains insufficient proof that every object is visually preserved.

[The MathLeading proposal #2674](https://github.com/storytold/wordcraft/pull/2674)
was still open on 28 October. The released math layout still returns box ascent without
that additional leading. No general equation-spacing or matrix fidelity fix is attributed to 0.12.0.

## New public controls

`tests/workflow/wordcraft_0120_fixture.ts` builds two DOCX variants with explicit
`doNotExpandShiftReturn=0/1`. Both include one Times New Roman 14-point run containing
ten ordinary spaces or ten NBSP characters, a justified manual line break, and narrow
30-point `Oremus` paragraphs with no bookmark, two zero-width markers at offset zero,
or a marker at offsets two and three. Offset two lies inside the natural Times New Roman
wrap; offset three alone would coincide with that boundary and miss an artificial break.
XML tests verify the controls' actual text, run properties, bookmark boundaries, width,
manual break and explicit compatibility flag. Real output measurements are separate.

## Measured results

All eleven previous inputs produce **byte-identical PDFs in 0.11.0 and 0.12.0** on
Linux/WSL. The two new controls expose the release changes; the combined corpus has
235 engine pages. Four large inputs preserve all 38 encoded image objects between
versions (13 + 6 + 13 + 6). None has an alpha mask, so mask preservation is not exercised.

Eleven inputs have fresh successful Word acceptance receipts, totaling **144 Word pages**
versus **143 engine pages**. The rebuilt coursework remains 69 versus 68 pages.
The two frozen legacy DOCX files are included only in engine comparisons, without
claiming a new Word acceptance; their table-heading failures are documented in the
[previous audit](2026-10-26-wordcraft-0110.md).

These page-wide fractions do not quantify rule compliance. The unmatched coursework
page contributes zero to the mean, so its page-count difference must be read alongside
the metric. Existing math/matrix differences remain, including tighter matrix row
spacing and different page flow. Full-height matrix brackets remain intact in the
visually inspected 8x8 control; equal four-page totals do not establish equal placement.

The new bookmark control changes from `Or / emus` in 0.11 to `Ore / mus` in 0.12,
matching the plain paragraph and Word. Two zero-width bookmarks at the start no longer
add an empty line: the marker-to-first-letter gap falls from about 48.5 to 24.5 points.
Ordinary paragraph spacing still differs from Word.

With expansion enabled, the manual-break line now reaches approximately 552.81 points
from the left paper edge, versus 552.89 in Word; 0.11 stops at 214.20. Disabling expansion
retains the short line. This fixes the selected behavior, not complete paragraph parity:
the inherited first-line indent and vertical placement still differ from the Word workflow.
The ten-space and ten-NBSP widths differ by less than 0.01 point in both engines and Word;
there is no new visible improvement for these Times New Roman glyphs.

The raw TOC update still fails the numbered-entry-inside-field check. Staging preparation
passes stale-result removal, dirty-flag cleanup, numbered headings inside the correct
outer field and source-preservation checks. The existing workaround is retained.

The first three original-image Word exports failed while a cold Python dependency was
downloading. After dependency preparation, only those three were repeated and accepted.
Failed and successful receipts both verify process cleanup; no validator was weakened.

## Platform result

All thirteen final inputs produce **byte-identical 0.12.0 PDFs on Linux/WSL and native
Windows**, 235 pages per set. Independent text, geometry and 96-DPI raster checks agree.
This includes eleven accepted-Word inputs and two separately labelled legacy inputs;
platform agreement does not give the latter a new STO acceptance.

## Measurement method and limits

Independent PDF checks use pypdf, PDFium and Pillow at 96 DPI and channel tolerance 16.
Page geometry, text, resources, unmatched pages and raster differences are recorded separately.
Pages are paired by ordinal, without realigning reflow. Changed-pixel fractions include white
page area and are not percentages of correct formatting. Page totals can hide opposite errors.

Word runs exclusively through `npm run accept:word -- <docx> --background-only`, with stable
saved/reopened pagination and exact owned-process cleanup. No Computer Use or desktop input is used.
SVG controls explicitly use print-quality Word export; this is not an original-pixel guarantee.
Legacy DOCX files remain separate from current accepted rebuilds and do not acquire STO acceptance
merely because both engines can render them.

Native macOS, ARM/RISC-V and a physical Linux host are not tested here. CI portability checks
cannot substitute for actual rendering on those hosts. Windows CLI calls cross the WSL path bridge;
command timings are not native performance benchmarks.

The practical manual checks remain in the [compatibility matrix](../wordcraft-compatibility.md).
Private report content and full generated files are not published. Temporary runtime archives,
DOCX copies, PDFs and logs are removed after compact evidence capture; installations and rollback
remain available.
