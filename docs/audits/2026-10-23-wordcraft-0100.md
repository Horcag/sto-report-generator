# Wordcraft 0.10.0: release and Word comparison

## Runtime and method

The integration requires official CLI **0.10.0**, released on 22 October 2026,
commit `9130181a5fdaee2293e67756fd5458c601489f3c`.
The previous 0.9.0 CLI remains available locally for rollback and comparisons.

| Official archive         | SHA-256                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| Linux x86-64 tar.gz      | `ca99ea350ba0aea4103fc8020cad98f051c58d9e9fcf670c119d810108cc45ff` |
| Windows x64 portable ZIP | `141d9458d776b4a664f20fbb0e2cd5619c327e0873abbc01bf4530dc339592fb` |

Both downloaded archives passed the release's SHA-256 checks. Both CLIs reported 0.10.0.
The installed Linux executable is selected through the existing local launcher;
the Windows executable is exercised from temporary storage. No GUI application is installed.

The comparison freezes each source DOCX, then runs the production rendering workflow with
0.9.0 and 0.10.0. The baseline adapter is the previous merged revision `498f4e0`;
the updated adapter retains the same rendering sequence. Both use the same licensed Windows
font files: Times New Roman, Cambria Math/Cambria, Arial, Calibri and Courier New.
The font preflight, selected font hashes, source hashes and PDF hashes are checked.
Private report originals are copied and never edited; their text and PDFs are not published.

Native Word references use `npm run accept:word -- <docx> --background-only`.
This makes one bounded invisible attempt, with no interactive retry, Computer Use,
keyboard/mouse control or desktop focus. Receipts must establish saved/reopened pagination,
content integrity and exact owned-process cleanup before a result is accepted.
Word's existing table/field/statistics repairs remain part of that workflow.

Independent PDF inspection uses pypdf, PDFium and Pillow at 96 DPI and channel tolerance 16.
Pages are paired by ordinal. Text, page geometry, font/image resources and changed pixels
are measured separately. Pixel differences include white page area and are not a percentage
of formatting correctness. Reflow can increase the metric without losing content.

## Relevant upstream fixes

These are upstream changes shipped in the release; our corpus measurements below are separate.

- [Times New Roman fallback, #2673](https://github.com/storytold/wordcraft/pull/2673):
  named substitutes take priority over generic font selection, avoiding Caladea when Liberation
  Serif is the intended substitute. Installed Times New Roman still matters for Word comparison.
- [Superscript/subscript line metrics, #3460](https://github.com/storytold/wordcraft/pull/3460):
  ordinary indexed runs no longer enlarge line height merely because they rise or drop.
  The change explicitly excludes inline OMML/Cambria Math metrics.
- [Equation arrays, #2690](https://github.com/storytold/wordcraft/pull/2690) and
  [#2691](https://github.com/storytold/wordcraft/pull/2691): rows without alignment points are centred.
- [TOC tab wrapping, #1840](https://github.com/storytold/wordcraft/pull/1840):
  the right tab and following page number move together, keeping the dot leader.
- [TOC field import, #2477](https://github.com/storytold/wordcraft/pull/2477),
  [content-control preservation, #2429](https://github.com/storytold/wordcraft/pull/2429) and
  [localized hyperlink styles, #3260](https://github.com/storytold/wordcraft/pull/3260)
  improve imported TOC content. They do not prove every TOC update or page number is correct.
- [Justified text, #3202](https://github.com/storytold/wordcraft/pull/3202):
  compatibility mode 15 uses revised space-shrink limits when breaking lines.
- [Explicit table width, #1728](https://github.com/storytold/wordcraft/pull/1728),
  [skipped grid columns, #1760](https://github.com/storytold/wordcraft/pull/1760) and
  [band sizes, #3429](https://github.com/storytold/wordcraft/pull/3429)
  cover additional table cases; they are not a general table-layout equivalence claim.
- [PostScript font names, #2500](https://github.com/storytold/wordcraft/pull/2500)
  improves exact face-name resolution. Variable font instances still have limitations.

The proposed [equation-leading fix #2674](https://github.com/storytold/wordcraft/pull/2674)
was still open when checked on 23 October. It is **not** part of 0.10.0.
Our scalable matrix delimiter conversion remains necessary and is preserved.

## TOC staging workaround

The installed-engine stale-field check caught a new 0.10.0 regression: the writer closed
an empty TOC field before its refreshed entry paragraphs. A retained semantic content control
blocked the special TOC field-span path; [upstream's versioned writer](https://github.com/storytold/wordcraft/blob/v0.10.0/crates/docx/src/write/story.rs)
and [control handover](https://github.com/storytold/wordcraft/blob/v0.10.0/crates/docx/src/read/mod.rs)
explain the interaction introduced by #2429.

The adapter now unwraps only semantic Table of Contents controls containing the actual TOC
field in its disposable prepared input. It preserves the field, switches, entries, formatting
and unrelated controls. Wordcraft can then recreate its own semantic wrapper and field span.
The canonical source DOCX remains unchanged. Strict checks still require stale text removal,
cleared dirty state and numbered entries inside the matching outer field boundaries.
This is an automatic integration workaround, not an upstream fix or a required manual edit.

## Reproducible controls

The public corpus contains both generator style presets, the 90-row table, math/appendix
controls, matrices up to 8x8 and nested/rectangular matrices, and the three-section document
with restarted page labels, headers/footers and multiline table rows.

`tests/workflow/wordcraft_release_fixture.ts` adds ordinary indexed text, long right-tab/dot-leader
paragraphs, justified Russian text, and aligned/unaligned equation arrays. The normal test runner
checks both presets and direct OMML placement; the installed-engine live suite renders the control.
The tab paragraphs exercise layout, not automatic TOC generation or web-imported fields.

An initial version of this new control contained an invalid XML wrapper. Native Word rejected it;
the control was repaired and a regression added. Only rebuilt results are valid audit evidence.
Word also exposed a text-integrity false alarm when it normalized a literal tab into an inline
XML tab element. The integrity check now canonicalizes equivalent inline whitespace while still
rejecting changed or reordered text and ignoring paragraph tab-stop definitions.

## Measured Word comparison

Nine final accepted Word references cover 139 PDF pages. Both Wordcraft versions also total
139 pages, but the totals hide opposite errors: C1 has 67 Word pages versus 66 Wordcraft,
while matrices have three Word pages versus four Wordcraft. Every Word receipt records
background-only execution, stable saved/reopened pagination and verified process cleanup.

| Case                           | Word pages | 0.9.0 pages | 0.10.0 pages | Pixel difference from Word, 0.9.0 | Pixel difference from Word, 0.10.0 |
| ------------------------------ | ---------: | ----------: | -----------: | --------------------------------: | ---------------------------------: |
| Public example, Samara preset  |          8 |           8 |            8 |                            2.440% |                             2.473% |
| Public example, default preset |          8 |           8 |            8 |                            2.440% |                             2.473% |
| 90-row table                   |         11 |          11 |           11 |                            3.124% |                             3.044% |
| Math and appendix              |          5 |           5 |            5 |                            0.641% |                             0.641% |
| Matrix controls                |          3 |           4 |            4 |                            2.600% |                             2.600% |
| Three sections                 |          7 |           7 |            7 |                            1.935% |                             1.935% |
| Release-specific controls      |          4 |           4 |            4 |                            1.191% |                             1.218% |
| Private coursework C1          |         67 |          66 |           66 |                           14.216% |                            14.146% |
| Private report R1              |         26 |          26 |           26 |                            7.357% |                             6.799% |

The mean pixel fraction includes unmatched pages as zero and therefore must be read together
with page counts: C1 and the matrix control each have one unmatched page. It is not a fidelity
score. Every case still differs from Word. R1 and the long-table control move closer under this
metric; the two examples and the new combined control move slightly farther away. There is
no uniform improvement across the corpus.

Visual inspection of the new public control confirms that unaligned equation-array rows now
centre instead of sharing a left edge. Wordcraft 0.10.0 is horizontally closer to Word there;
vertical positions still differ. The indexed-text and long-tab controls do not show an obvious
new visual improvement in these particular paragraphs. Their inclusion does not prove every
upstream fix is exercised. Full-height matrix brackets remain unchanged and correct.

Math, matrix and three-section PDFs are byte-identical between the final 0.9.0 and 0.10.0
workflows. Text changes in private reports are layout/extraction observations, not evidence
of content loss; the original DOCX hashes remain unchanged. Private table pagination still
has unsupported/ambiguous-container warnings and is not promoted to verified table parity.

The 90-row table preserves every row and three continuation captions, with matching row
boundaries 1-28, 29-58, 59-88 and 89-90 on pages 6-9. The section control preserves all 40
multiline rows and two continuations; both workflows show page labels `1,2,i,ii,1,2,3`.

A separate Linux run without Office font files has eight pages in both versions and uses
Liberation Serif/Mono and DejaVu Math TeX Gyre in both. Its mean changed-pixel fraction
between versions is 0.435%. This host already chose Liberation Serif before the update,
so it does not demonstrate the newly corrected Caladea fallback path.

## Platform result

The final 0.10.0 workflow ran on Linux x86-64 under WSL and native Windows x64 for all nine
frozen sources. All nine PDFs, totalling 139 pages, are byte-identical between those platforms;
independent text, geometry and raster checks agree. Windows execution used only a temporary
CLI and path translation, with the same installed Windows font files. This establishes agreement
between these builds for this corpus, not equivalence to Word or acceptance on macOS.

## Remaining limits

The matrix control still occupies three Word pages and four Wordcraft pages. Full-height
matrix brackets remain correct; this release does not close the spacing/pagination gap.
Identical page counts in other cases do not establish identical layout.

No native macOS, ARM, RISC-V or standalone physical Linux execution is claimed. CI quality checks
on an operating system establish code portability, not native renderer equivalence.
The Linux/Windows renderer measurements cover the exact x86-64 builds and font files only.

The versioned upstream [layout limits](https://github.com/storytold/wordcraft/blob/v0.10.0/docs/layout-parity.md)
still cover line metrics, font substitution, table width conflicts, autofit, floating/nested tables
and mathematical layout. The [format limits](https://github.com/storytold/wordcraft/blob/v0.10.0/docs/file-format-parity.md)
still include ignored mathematical defaults such as `m:mathFont` and `m:dispDef`.
Upstream corpus statistics are not acceptance results for our reports.

Use the [compatibility matrix](../wordcraft-compatibility.md) for practical manual checks,
and the [renderer contract](../architecture/wordcraft-renderer.md#verification) for commands.
Full temporary binaries, DOCX/PDF copies and comparison payloads are removed after inspection;
compact hashes, measurements and selected public visual panels retain the result.

The manifest warnings identify when this workaround runs. Remove it only after a later pinned
upstream release passes the raw and prepared stale-field controls, including field boundaries,
numbered entries, source preservation and repeated update/save cycles. Keep the regression.
