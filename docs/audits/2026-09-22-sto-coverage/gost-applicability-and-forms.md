# Применимость ГОСТ и формы отчётов (#28)

Проверка проведена 24.09.2026; библиографическая классификация уточнена 25.09.2026. Эта запись ограничивает выводы подтверждёнными пунктами стандартов и локальной методичкой. Статусы всех специальных требований остаются в [full-matrix.csv](full-matrix.csv), строки `SPECIAL-B01`–`SPECIAL-B46`; запись не меняет статусы неподдерживаемых атомов на «выполнено».

## Источники и приоритет

- ГОСТ Р 7.0.5-2008: [карточка Росстандарта](https://protect.gost.ru/gost/details/2eef7820-44bc-49a4-bf1f-fe51c54039dc), [доступный скан официального издания](https://library.istu.edu/content/gost-r-7-0-5-2008.pdf). Пункты 4.1–4.5 определяют библиографическую ссылку; 4.6 перечисляет внутритекстовые, подстрочные и затекстовые ссылки. Генерируемое `[1]` — отсылка к **затекстовой** записи по 7.4.1, а `[1, с. 12]` — отсылка к фрагменту по 7.4.2. Внутритекстовая ссылка раздела 5 содержит описание в круглых скобках и генератором не поддерживается. Применяется, когда отчёт содержит ссылки.
- ГОСТ Р 7.0.100-2018: [доступный скан официального издания](https://ifap.ru/library/gost/701002018.pdf). Раздел 1 прямо исключает библиографические **ссылки** из области действия этого стандарта. Он описывает библиографическое **описание** объекта в списке источников. Пункты 4.3–4.4 задают области и обязательность элементов; 5.8.3 регулирует URL, дату обращения и условие доступа для сетевого ресурса. Нельзя механически требовать все элементы полного описания от каждой ссылки по 7.0.5.
- ГОСТ Р 7.0.108-2022: [карточка Росстандарта](https://protect.gost.ru/gost/details/df775619-cc9b-4cea-af6e-83e31a0aab9e), [доступный скан официального издания](https://library.istu.edu/content/gost-r-7-0-108-2022.pdf). Пункт 4.3 требует адрес конкретной электронной версии при ссылке на неё; 5.3 отсылает к 7.0.100 по общим областям описания. Пункты 5.3.1–5.3.5 уточняют заглавие, тип ресурса, выходные сведения, объём и последовательность примечаний для электронного ресурса. По 5.3.3 сведения о месте, издателе и дате опускаются, если их нет на объекте. Применяется только к электронным источникам; отдельные пункты условны по типу ресурса и наличию сведений на самом объекте.
- Для форм Самарского университета использованы локальные `reports/practice_ppb_2026/source_materials/MU_Oform_VKR_Bak_Mag_2023.pdf` (таблица 1, с. 5–6; титул и задание, с. 7–9) и `.agent-work/full-sto-audit/extracted/virtual6_vvs_976--Obrazcy_oformlenija_VKR_2022_2.txt` (образцы титула, задания и реферата бакалавра). Локальный образец формы имеет приоритет перед общим ГОСТ по геометрии университетского титула. Для магистерского титула точного визуального эталона в доступных материалах не найдено; использованы общие поля методички и явная подпись уровня магистратуры.

## Приёмка образцов

Для каждого профиля создан отдельный свежий scaffold, собран DOCX (`--renderer portable --validate`) и выполнено `npm run accept:word -- <docx>`. Word сохранил DOCX, открыл его повторно с тем же числом страниц, проверил стили, экспортировал PDF. Результаты находятся в `.agent-work/<имя>/build/<имя>.acceptance.json` и соседних `.accepted.pdf`:

## Остаток по матрице B01–B46

Дополнение 25.09.2026: source preflight и генератор используют одно средство чтения BibTeX. Проверяются дубли ключей, синтаксис BibTeX и цитат, поля процитированных записей и календарная дата обращения. Генератор описаний останавливает сборку без заглавия и не создаёт фиктивные место, издателя и год; для сетевого документа без выходных сведений они опускаются по ГОСТ Р 7.0.108, п. 5.3.3. URL и дата обращения теперь сохраняются также в описаниях сетевых статей, книг и составных частей. Поле `editor` книги выводится как сведения об ответственности. При цитировании фрагмента `[@key, с. 12]` превращается в `[N, с. 12]`, повтор ключа сохраняет номер. Эти проверки покрыты тестами исходника, формирования описаний и DOCX; они не удостоверяют содержательную точность метаданных и URL.

| Атомы   | Автоматическое доказательство после дополнения                                                                                                       | Оставшаяся граница                                                                                                                   |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| B01–B07 | Для поддержанных типов проверяются присутствующие поля; сборка без заглавия невозможна, `editor` выводится, фиктивные выходные сведения не создаются | Автор сверяет установленное/редакторское заглавие, оценочную дату и физический объём с объектом; условные случаи остаются частичными |

- `B01`–`B28`: описания печатных и сетевых ресурсов по 7.0.100 остаются частичными. Средство форматирования и source preflight проверяют несколько обязательных полей и создают записи поддерживаемых типов, но не покрывают все условные/параллельные области, серии, идентификаторы, ограничения доступа и случаи без доступных выходных данных. Раздел 1 7.0.100 запрещает переносить эти требования на каждую внутритекстовую ссылку.
- `B29`–`B39`: электронные ресурсы по 7.0.108 частично покрыты маршрутом `site` и общими проверками URL/даты обращения из #12. Не подтверждена автоматическая проверка того, что URL указывает именно на цитируемую версию (`B29`), и не реализованы все специальные типы ресурсов (`B34`–`B39`) и полная последовательность примечаний.
- `B40`–`B46`: поддерживаются нумерованные затекстовые ссылки (`B40`) и отсылки `[N]`/`[N, с. X]` к ним. Исходная классификация `B41` как «числовой внутритекстовой ссылки» была ошибочной: раздел 5 не реализован. Подстрочные, специальные повторные, комплексные и архивные ссылки (`B42`–`B44`, `B46`) остаются без отдельного движка; электронное примечание (`B45`) частичное. Их нельзя объявлять закрытыми за счёт нового профиля формы.

Таким образом, #28 реализует подтверждённые профильные формы и ограниченные проверки. Полная сертификация по трём библиографическим ГОСТ остаётся за пределами доказательств; для неё нужны отдельные типовые корпуса и сверка каждого применимого условного пункта.
