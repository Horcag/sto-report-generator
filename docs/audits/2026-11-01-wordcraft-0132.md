## What upstream shipped

The release contains 62 commits after 0.12.0. Release claims are kept separate from
measured behavior on this corpus.

- [#2810](https://github.com/storytold/wordcraft/pull/2810): zero-width/zero-height
  paragraph frames remain in normal flow; direct explicit-zero resets survive save/reopen cycles.
  This does not establish compatibility for positive-size grouped frames.
- [#1883](https://github.com/storytold/wordcraft/pull/1883): additional minimum width
  from spanning cells is distributed using preferred column widths, including nested
  tables; each column retains its own minimum. Automatic widths still share equally.
- [#4706](https://github.com/storytold/wordcraft/pull/4706): built-in heading1 through
  heading9 styles can supply an omitted outline level. Explicit levels are preserved;
  custom styles and heading10 are outside this fallback. Localized TOC styles and
  multi-column TOCs were already present in 0.12.0.
- [#4863](https://github.com/storytold/wordcraft/pull/4863): optional `snapToGrid` and
  `webHidden` values survive DOCX save/reopen cycles in runs and styles. `webHidden` remains
  distinct from `vanish` and does not hide text in Print Layout.
- [#4881](https://github.com/storytold/wordcraft/pull/4881): cycle-safe Caption style
  ancestry extends caption discovery for cross-references and Tables of Figures.
  This is not general support for arbitrary SEQ field definitions.
- [#4898](https://github.com/storytold/wordcraft/pull/4898): corporate authors retain
  their whole names in DOCX citation and bibliography processing. Our generator
  formats its own bibliography; this upstream change does not replace that formatter.
- [#4726](https://github.com/storytold/wordcraft/pull/4726): Chart/SmartArt labels use
  font-face fallback runs for screen, PNG and PDF rendering. Chart-specific `c:txPr`
  Latin/East Asian font settings are still not read; labels still use the body font.

[The MathLeading proposal #2674](https://github.com/storytold/wordcraft/pull/2674)
remains open and unmerged on 1 November. The release comparison does not change
`crates/layout/src/math.rs`. No general equation-spacing or matrix fidelity fix is
attributed to 0.13.2. The versioned [matrix layout implementation](https://github.com/storytold/wordcraft/blob/2be33e6dc9c246a57995b131ee85491ce81de328/crates/layout/src/math/structs.rs#L290-L334)
still uses fixed em-based column and row spacing. This source limitation does not
quantify the actual difference from Word on any particular matrix.

### Spanning-cell width control

`tests/workflow/wordcraft_0132_fixture.ts` adapts upstream #1883 to STO cell padding.
Each of three tables has a header and a data row. The first spans four columns with
an opaque 300-by-30-point banner and preferred widths; the second uses automatic
widths with the same banner; the third uses only text minima. XML checks verify
these distinctions, including removal of derived cell-width preferences in auto controls.
Independent PDF measurements recover column borders and compare the same table row.

### Existing controls and images

Matrix output remains byte-identical between engine versions: four pages in both
engines and Word, with existing mathematical spacing and placement differences.
The 90-row control retains every row, the same row/page boundaries and three
continuation captions. The three-section control retains forty rows, two continuation
captions, headers/footers and decimal/Roman page-number restarts.

The raw TOC update still fails the numbered-entry-inside-field check. Staging
preparation passes field boundaries and source preservation, so the workaround remains.
Four large inputs preserve all 38 encoded image objects between engine versions
(13 + 6 + 13 + 6). No recorded image has an alpha mask, so alpha-mask preservation
is not exercised by this comparison.

## Platform result

All fourteen final 0.13.2 inputs produce byte-identical PDFs on Linux/WSL and native
Windows, totaling 236 pages per set. Independent text, geometry and raster checks agree.
The two legacy inputs remain outside fresh Word acceptance.

Strict family preflight passes on both hosts. Linux explicitly loads four to nine
licensed font files per case in both engine versions, with matching file hashes. Windows uses
installed families from its native catalog without reloading those files. The selected
native catalog files are not independently hashed. Output identity establishes the
observed platform agreement, without filling that font-provenance gap.

## Resource failures and retry boundary

Initial concurrent runs exceeded allocation/time limits in both 0.12.0 and 0.13.2.
The failed Linux cases were repeated after reducing load; the thirteen original
inputs then produced byte-identical PDFs across both versions, totaling 235 pages.
These resource failures do not establish a renderer regression.

The current coursework also exceeded the previous 180-second background Word
budget, including a serial retry. That retry completed save/reopen and PDF export,
but timed out during final table verification. Its receipt reports failure and
verified process cleanup; exported files alone do not grant Word acceptance.
The background/large-document per-attempt budget is now 300 seconds. The isolated
Word retry passed in 121.45 seconds after host load decreased. That observation
does not establish that the deadline change alone caused success or improved speed;
the new limit provides bounded headroom for final verification. The accepted receipt,
including stable saved/reopened pagination and cleanup, establishes acceptance.

## Measurement method and limits

Each engine receives the same DOCX bytes. Independent PDF comparison records page
counts, geometry, normalized text, resources and raster differences separately.
Pages are paired by ordinal without realigning reflow. Raster comparison uses
PDFium and Pillow at 96 DPI with channel tolerance 16, with pypdf for independent
PDF inspection. Changed-pixel fractions include white page area and are not
percentages of correct formatting. Page totals can hide opposite errors.

Word runs exclusively through `npm run accept:word -- <docx> --background-only`,
with stable saved/reopened pagination and exact owned-process cleanup. No Computer
Use or desktop input is used. Successful engine rendering of a legacy DOCX does
not grant it a new STO acceptance. The user-facing process comparison includes
field updates and table repairs from the generator's Word workflow.

Native macOS, ARM/RISC-V and a physical Linux host are not tested here. Native
Windows CLI output is compared separately from Linux/WSL output; that agreement
cannot establish Word layout parity. WSL-to-Windows bridge timings are not native
performance benchmarks. Licensed fonts remain local.

Historical results remain in the [0.12.0 audit](2026-10-28-wordcraft-0120.md).
Cross-audit differences can include generator/input changes and must not be
interpreted as engine-only improvements. The practical checks remain in the
[compatibility matrix](../wordcraft-compatibility.md).

## Development-tool security maintenance

The final security gate pins development-only `glob` 14.0.3 and `minimatch` 11.0.3
for [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)
and [GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4).
Four lockfile package nodes change, including their development-only helper packages;
production dependencies and DOCX generation remain unchanged. Dependency audit reports
zero vulnerabilities, and lint plus focused glob/matcher/coverage-tool smoke checks pass.
The gallery is regenerated through background Word acceptance because its provenance
fingerprints include the package files. These tooling changes do not alter the frozen
DOCX inputs or invalidate the paired renderer measurements above.
