# Table formatting and validation contract

## Normative sources

- University standard: [СТО 02068410-004-2018](https://ssau.ru/docs/sveden/localdocs/STO_SGAU_02068410-004-2018.pdf), section 6.2.
- Research reports: [ГОСТ 7.32-2017](https://cs.msu.ru/sites/cmc/files/docs/2021-11gost_7.32-2017.pdf), section 6.6.

The university teaching scan distributed as a 2019 file identifies itself as the 2018 standard.
Its table section and the amended university edition have different subsection numbering.
The STO references below use the teaching scan; consult section 6.2 and the rule text when using another edition.
The public university PDF has an incomplete searchable text layer; the teaching scan was reviewed visually.

ГОСТ 7.32-2017, 6.6.6 explicitly centers column headings and left-aligns row headings.
The reviewed STO table section does not explicitly prescribe horizontal or vertical centering.
The generator centers every column heading independently of Markdown column alignment and preserves data alignment.
A numeric first column is not automatically treated as a row-heading column.
Neither universal body-cell centering nor mandatory vertical centering follows from these sections.

## Structural safeguards

These document-integrity checks are not additional requirements attributed to STO:

- Header/separator/body column counts agree before `marked` can truncate or pad cells.
- GFM optional outer pipes, short separators and single-column tables are supported.
- Literal pipes use GFM escaping (`\|`), including code spans and inline formulas.
- Fenced/indented code, HTML examples and YAML are excluded from source-table diagnostics.
- DOCX spans and row omissions agree with the grid; preferred `tcW` values are not exact widths.
- Explicit false repeat flags are respected; repeated headings must be contiguous at the start.
- Paragraph inheritance, table conditions, merged headings and nested data tables are inspected.
- Formula layout tables and title-page tables before the referat are excluded from data-heading rules.
- A line break alone does not make an empty data cell meaningful.
- Word acceptance rechecks heading alignment, grid structure and repeat order and records `tableChecks`.

Cell margins of 57 DXA vertically and 108 DXA horizontally, row non-splitting and the default table font are project conventions.
They are not universal numerical requirements of ГОСТ 7.32-2017.

## Regressions and routine use

`npm test` and the coverage gate execute:

- `tests/parser/table_headers.test.ts`: varied data alignment, multiline headings, repeat flags and unsplit rows.
- `tests/source-preflight/table_rules_test.ts`: malformed shape, escaping, masking and exact line diagnostics.
- `tests/source-preflight/table_caption_rules_test.ts`: number/label forms, punctuation and prose exclusions.
- `tests/validator/table_layout_test.ts`: inherited formatting, merged/nested tables and structural mutations.
- `tests/validator/table_cells_test.ts`: empty/merged cells and disabled/active diagonals.
- `tests/workflow/word_acceptance_tables_test.ts`: invalid accepted artifacts produce failed manifests.

Run `npm run check:source -- <report>` before building and `npm run generate:report -- <report> --renderer portable --validate`
for source plus XML validation. Use `npm run accept:word -- <docx>` for final Word pagination and PDF export,
then validate the accepted DOCX. Passing XML does not prove border readability, sensible grammar, or absence of visual clipping.
