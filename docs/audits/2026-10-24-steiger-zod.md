# Steiger и исправленная ветка Zod

Дата проверки: 24 октября 2026 года.

`npm audit` сообщал о трёх зависимых пакетах с высоким уровнем риска:
Steiger, Zod и zod-validation-error. Причина – одна
[уязвимость Zod при проверке слишком больших коллекций](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).
Исправление доступно в Zod 4.6.6. Ветка совместимости `/v3` продолжает
обходить элементы массива после превышения ограничения; замена версии с
сохранением этой ветки не устраняет причину проблемы.

В репозитории закреплён Steiger 0.7.0. Его зависимости переопределены только
внутри собственной цепочки: Zod 4.6.6 и zod-validation-error 4.0.2.
Steiger получает ограниченное исправление для API Zod 4:

- перечисление ключей конфигурации проверяется через `partialRecord`, чтобы
  разрешать включение части известных правил и отклонять неизвестные;
- схема функций сохраняет аргументы, `this` и проверку результата, включая
  синхронные функции и Promise;
- исполняемые плагины берутся из проверенной конфигурации, чтобы обёртки
  проверки результатов применялись при реальном запуске правил.

Исправление устанавливает [postinstall-скрипт](../../scripts/quality/patch_steiger_zod.cjs).
Он проверяет точные версии зависимостей, исходный и итоговый SHA-256 файла
Steiger. Неожиданная версия или изменённый файл останавливают установку.
Повторный запуск безопасен. В production-установке без Steiger скрипт
завершается без изменения файлов. `npm ci` воспроизводит установку и патч;
исключений для аудита и отключённых архитектурных правил не добавлено.

[Регрессионный тест](../../tests/shared/steiger_zod_security_test.ts) проверяет
настоящую зависимость Steiger: слишком большой массив отклоняется до обращения
к его элементам. Дополнительно проверяются частичная и неверная конфигурация,
корректные и неверные результаты синхронных/асинхронных правил, ошибки функций,
идемпотентность патча и обнаружение запрещённого импорта из `shared` в `features`.

Проверено: чистый `npm ci`, `npm audit --audit-level=low` без уязвимостей,
`npm run fsd:check` и целевые регрессии. Полный набор запускает этот тест через
`tests/run_all_tests.ts`. При обновлении Steiger нужно заново проверить
совместимость и контрольные суммы; несовпадение не следует обходить.

Основания:

- [исправление Zod](https://github.com/colinhacks/zod/commit/a0ebf970f2d752e5f58527cd2942ff48be4f46bd);
- [изменения API Zod 4](https://zod.dev/v4/changelog);
- [исходная проверка конфигурации Steiger](https://github.com/feature-sliced/steiger/blob/master/packages/steiger/src/models/config/validate-config.ts).
