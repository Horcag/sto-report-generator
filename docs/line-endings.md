# Переводы строк

Текстовые файлы в репозитории используют LF. `.gitattributes` задаёт `text=auto eol=lf`,
`.editorconfig` задаёт LF для редакторов, а Prettier применяет `endOfLine: lf`.
Эти настройки не меняют кодировку файлов.

После обычной установки зависимостей установите локальные проверки:

```bash
npm run hooks:install
```

Проверка LF запускается перед сохранением изменений в Git и отправкой изменений, а также отдельно в CI.
Для ручного запуска:

```bash
uv run python scripts/quality/check_line_endings.py
```

Команда проверяет исходные байты файлов в индексе Git и рабочем каталоге.
Поэтому нормализация при добавлении файла в индекс не скрывает CRLF в рабочем файле,
а файл с LF в рабочем каталоге не скрывает CRLF в уже подготовленном объекте Git.
Для этой проверки нужен настоящий Git-репозиторий; она не входит в проверку снимка без `.git`.

Автоматически определяемые бинарные файлы, символические ссылки и вложенные репозитории пропускаются.
Если конкретный тестовый файл намеренно содержит другие переводы строк,
объявите её бинарным исключением в `.gitattributes`, указав точный путь:

```gitattributes
/tests/fixtures/example.raw -text
```

Такое исключение сохраняет исходные байты. Не добавляйте исключения для обычных текстовых исходников.
После исправления переводов строк добавьте исправленный файл в индекс повторно и запустите проверку.
